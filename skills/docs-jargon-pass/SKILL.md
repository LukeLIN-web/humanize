# 文档术语盲读审查(盲读 → 查证 → 改写)

## 核心原则

**顺序不可颠倒。** 先盲读、后看仓库。看过代码之后你就再也看不见术语了——每个自造词都会自动被脑补成"显然的意思",这正是原作者当初写出这些词的原因。第一趟的唯一目的是保留"看不懂"这个信号,它一次性、不可再生。

**盲读的困惑必须落盘。** 第二趟要读代码,读完记忆就被污染了,记不住自己当初卡在哪。

**读读者看到的样子,不读源码。** md 直接读原文。HTML 读去掉标签、CSS、脚本、内嵌图片后的页序文本——源码里一屏 base64 和样式会把正文淹掉,而表头、图注、SVG 图上画的字在源码里和它们落在页面上的位置隔得很远。抽文本用标准库就够(没有 w3m / lynx / pandoc 的机器也能跑):

```bash
python3 -I - page.html > page.txt <<'EOF'
import html.parser, sys
BLOCK = {"p", "li", "tr", "h1", "h2", "h3", "h4", "dt", "dd", "figcaption", "caption", "br", "div", "section", "footer", "header", "text", "title"}
class Text(html.parser.HTMLParser):
    skip = 0
    def handle_starttag(self, tag, attrs):
        self.skip += tag in ("script", "style")
        if tag in BLOCK: print()
        if tag in ("td", "th"): print(" | ", end="")
    def handle_endtag(self, tag):
        self.skip -= tag in ("script", "style")
    def handle_data(self, data):
        if not self.skip and data.strip(): print(" ".join(data.split()), end=" ")
Text().feed(open(sys.argv[1], encoding="utf-8").read())
EOF
```

**读者不止一个。** 盲读时轮流装成这三种人:

| 读者 | 手里有什么 | 判定 |
|---|---|---|
| 正文读者 | 读到这一行为止的全部正文 | 定义必须先于首次使用 |
| 表图读者 | **只有这张表/图、它的标题和图注**,以及它之前的正文 | 表头、图注、图上画的字,若只在后文定义,对它的读者就是没定义 |
| 仓库外读者 | 只有这一页——没有你的机器、没有 `outputs/` 目录树、没有 memory、没有前几轮结果页 | 页面要离开仓库(发布成网页、发给合作者)时才有这种读者;机器名、路径、产物名对他是空指针 |

表、图注、页脚都是**独立阅读单元**——读者翻表的次数远多于逐行读正文。

## 第一趟:逐个盲读

先 `ls <目标目录>/*.md <目标目录>/*.html` 列清单,建 ledger 目录,HTML 先按上面抽成 `.txt`,然后一个一个来。读第 N 个文件时:

- 只 Read 这一个 md(或这一个抽出来的 `.txt`)。**不读**别的 md、不读 README、不读代码、不 grep、不看 git log。
- 允许的例外只有"文件系统管道":列清单的 `ls`、建目录的 `mkdir`、抽文本、写 ledger。**禁的是读任何其他文件的内容**,不是禁一切命令。
- 装成第一次进这个项目的同行:懂这个领域,但没读过这个仓库、没读过配套的 plan 页和前几轮结果页。页面要离开仓库时,再装一遍仓库外读者。
- **定义晚于使用,算问题。** 读到第 60 行才补上的定义,救不了第 12 行那个已经被卡住的读者。这类照记,`首次出现` 行必须准。

> 隔离提醒:如果本次会话已经读过这个仓库的代码,你已经污染了,盲读结果不可信。此时把每个文件派给一个独立 subagent 去盲读(每个 agent 只给一个文件路径、禁止它读其他文件),每个 agent 交一份 ledger,你只做汇总不做补充。

### 记什么:三种信号

- **卡住**(A/B 组)——必须停下重读,或必须前后翻页才能继续。能带着一个临时含义按正常速度读下去、且后文没有推翻它的,不记。
- **空转**(C 组·废话)——读得毫不费力,但读完说不出这句在这干什么:它不定义、不主张、不配置。判据是**删句测试**:删掉这句重读前后段,没有任何结论、定义或设置失去支撑,就记。
- **血统**(A 组·内部名与产物血统词)——**上面两个信号都抓不到它**:它读得顺,所在的句子又承重。它是产物树漏进散文:`outputs/` 下的目录名、checkpoint 名、修饰语「补跑的那份」「上一轮的枚举」「重打过的副本」「第三次扫描」。对每个*重/补/上一轮/旧/副本/第 N 次*修饰语多问一句:「它告诉我送进模型的输入有什么不同?」答不出就记,置信度写 `no idea`。这一组不靠读感,第二趟还要 grep 补扫。

不要把"每个没见过的名词"都记进去——那等于什么都没标。生僻但不卡壳的口语词放过;**含义会漂移的词必须记**(同一个词第三次出现时你又得重猜 = 记)。

**量的校准:** 卡住的承重条目通常 5–15 条。超过 20 条说明这不是措辞问题而是结构问题——**停止逐词记录,直接写文档级判定**。空转条目超过 ~15 条同理:整篇在写流水账,文档级判定里建议整篇瘦身,本技能只处置撞见的这几条。

### 类型

**A 组 · 删词/换词/补定义能修的**

- **自造词**——像术语,但这个领域没这个说法。含一个高频子类:**概念是领域标准的,但中文写法是自造的**(如"亚随机"↔ 通行写法"低于随机水平 / below chance")——最容易漏,因为它读起来像个正经术语。英文文档里同类的是**组内中文黑话直译**(`口径→caliber`、`考场→court`):检验法只有一条,这个词在本领域公开文献里是这个意思吗。
- **名字晚于数字**——"每块 600 秒""取前 3 个""上限 12":数字照写没问题,但**它配置的那个东西必须已经被命名过**。修法是让名词先出现,不是删数字。
- **缩写 / 记号无图例**——首次出现即缩写或符号,全文不展开;或定义晚于使用(标题、摘要、表头、图上用了正文才定义的记号)。
- **悬空指代**——"那个 gate""五互斥终局""第三层":哪个?哪五个?哪三层?
- **名不副实**——名字暗示 A,实际是 B。含字段名与紧跟其后的注释互相打脸的情况。
- **同物异名 / 一词多义**——同一篇里两个词指一个东西,或一个词指两个东西。
- **内部名**——仓库外读者手里没有对应物的名字:机器名、用了几台机器几张卡、本机路径(`/home/…`、`~/…`)、`outputs/` 下的目录、评测目录、checkpoint、示教/数据集名、临时产出名、memory 条目名。仓库内的结果页,这些只许待在出处那一节,不进结论句;页面要离开仓库,一律不写。
- **产物血统词**——修饰语在说"这是哪一代产物"而不是"输入有什么不同"。卡住门槛永远抓不到它,判法换成上面那个问题。

**B 组 · 换词修不了的**(盲读者比任何人都容易发现,因为你没有先验去替它圆场)

- **隐含前提**——句子通顺,但要先知道某个没写出来的外部事实才成立。
- **断句歧义**——中英混排、缺标点导致两种读法含义相反("无 NARROW、无关证据动作")。
- **数值互斥**——同一篇里两个数像是同一个量却不相等:可能是两个不同的量,也可能是错。盲读者分不出来,正是问题所在——记下,第二趟对账。
- **自相矛盾**——摘要断言 A,正文撤回 A;同页两处数字/结论打架。**这是文档 bug,不需要看代码就能判,单独报,不许靠改措辞抹平。**
- **数目不自洽**——号称"四源"实际是 3×2 六格;同一份数据两处给不同条数;并列项报数规则不一致。
- **一句话塞太多**——单个术语都没问题,但一句里堆了十几个专名,任何速度都读不动。处置是拆成列表,不是换词。

**C 组 · 废话**(不是看不懂,是没内容;处置只有删或降级,没有"改写"选项。判死生要全文语境,所以 C 组**不吃盲读隔离**:盲读只标记空转句,判定放第二趟)

- **无中生有**——主语是一个不存在的东西:"X 没有报这个设置的数""这一格官方没有数"。判死生只看:**读者在这张表/图里看得见这个空缺吗?** 看得见(某格是 `—`、行数比别处少)→ 留成表注一短句;看不见 → 删。
- **流水账**——过程叙事:老的错误结论、新旧对照("69.0→71.2")、"曾记 X"、"已删掉过一项坏数据"、push/暂存状态。
- **记账计数与自辩**——"计入 113/144""我们报这个而不是那个,是因为……":过删句测试就记。

### ledger 格式

写到 `.humanize/jargon/<UTC时间戳>/ledger-<文件名>.md`,**一个源文件一份 ledger**(subagent 并行时天然不冲突;汇总时也不必合并)。

用分块、不用表格——`卡点`和`我猜是`是长句,表格会把它们压成一行。每条:

```
### N. <一句话标题>
- 首次出现:file.md:12          ← 第二趟按这行改,必须准(HTML 写抽出文本的行号 + 原文一段,第二趟回源码定位)
- 其它出现::31 :44 :88         ← 只列让理解更糟的那几处,不用穷举
- 原句:<逐字抄,别转述>
- 类型:自造词
- 卡点:<为什么读不下去,一句话>
- 我猜是:<你的猜测>  置信度:sure | guess | no idea
- 严重度:承重 | 局部 | 表面
- 读者:正文 | 表图 | 仓库外      ← 表图读者的词改表头/图注自足,仓库外的词只删不补
```

C 组条目字段更少(废话不需要猜,只需要删句测试):

```
### C-N. <一句话标题>
- 位置:file.md:88
- 原句:<逐字抄>
- 删句测试:删掉后受损的结论 = 无      ← 写得出受损者就不是废话,改判 keep,不进 ledger
- 处置:删 | 降级表注
```

- **置信度**衡量*你*有多确定——第二趟拿它验证这个词的误导性有多强。
- **严重度**衡量*读者*被伤得多重:**承重**=全文结论挂在它上面;**局部**=只影响这一节;**表面**=读着别扭但不影响理解。二者独立。

ledger 末尾另开两节:

- **文档级判定**——不锚在任何行号上的整篇问题。最常见的一条:*本页不是独立文档,是对某份 plan 的 diff*(症状:一半的悬空指代都"翻开 plan 十秒就能答")。正解是加一个"前置概念"小节,不是逐词改写。也放:中英混排约定、密度问题、整篇在写流水账。
- **良品名单**——你专门判定过"这是真术语,别动"的词(`Holm 校正`、`聚类 bootstrap`、`prefill`、`oracle`、`LoRA`)。不写下来,第二趟会重新纠结甚至把它们改成大白话。

## 第二趟:查证 + 改写

现在才允许读代码和其他文档。**注意 grep 的是这篇文档所属的那个仓库**——目标文档可能不在当前 cwd 的仓库里。

先按 `严重度` 排序,但**排完先找承重条目之间的共同根因**——它们往往有一半出自同一个病(最常见:全是 plan diff),一节小节能一次干掉六条。之后表面条目可以整批放过。

**改之前先对账。** `grep -rn 原词` 的命中率比想象中低:承重条目里的核心词往往在代码里叫别的名字(「片加权」= `piece_mean`)。有效顺序是:**先把 artifact / 数据文件拉出来,跟文中每个数字逐个对一遍**,再去 grep 词。B 组的"数值互斥"在这一步判。文档里最严重的错通常是数字错,而数字错只能这样找出来。

**B 组不进改写流程**:自相矛盾、数目不自洽、数值互斥 → 直接列给用户(这是 bug,信哪个由用户定);断句歧义、一句话塞太多 → 改结构(加标点/拆列表),不换词;**隐含前提 → 补口径 + 同时报**(作者脑子里有一套没写下来的约定,补完还得让作者确认补对了)。

**C 组在改写前处置,只有两个动作**:①默认**整句删**,删完重读该段——被删句喂养的"这个对比""那一行"会跟着悬空;反跑删句测试,若某个结论真的少了支撑,恢复原句改判 keep。②缺席确实要交代的(表里有 `—` 等着解释),降级成表注一条,再删正文句。显著性限定词、划范围的分母、让对比不公平的设置差异不许跟着整句陪葬——缩成一个形容词或一条表注活下来。

**先看文档级判定**:如果结论是"需要一个前置概念小节",先写那一节,写完后一大批悬空指代和缩写条目会自动消解。被这一节收编的条目,`首次出现` 行号作废——别再回去重复插一遍。

A 组逐条处置。先查 ground truth:这个词在代码里对应什么?实际行为是什么?**该词描述的事和代码做的事不一致 → 文档 bug,单独报,不许靠措辞抹平。** 一致的,按下面四个动作**从上往下试,能停在第 1 条就别走到第 4 条**:

> **没有必要不要新增名词。** 读者看不懂一个词,默认答案是删掉它或换成文档已经在用的词,
> 不是给它补一句定义。补定义把"读者的困惑"升级成"读者必须记住的负担",名词表越长越难读。

1. **删掉这个词**(不是删整句)——句子改用已有的词把同一件事说出来。
2. **换成文档里已经在用的词 / 领域通行叫法**。第一顺位是文档自己:重用已有的词是零新增名词,搬一个文献里的标准词仍然是新增一个名词。换的是领域标准叫法时,首次出现处保留原词一次:`标准词(仓库内旧称 X)`。
3. **删掉整句**——这个词全文只用一次、删了不损失任何结论。这一条比想象中常用。
4. **首次出现处补一句定义**(≤1 个从句,锚到最近的标准概念)——只有前三条都不成立时才用:概念真实存在、文档里没有同义词、领域也没有现成词,且它承重到不能删。

两类例外直接走固定处置,不过这四步:

- **内部名**:页面要离开仓库 → 删,出处留在仓库内的源页;仓库内的结果页 → 挪进出处那一节。**绝不补定义**——给产物名下定义等于把产物树搬进页面。删了之后句子还缺东西,写出那东西的*内容*("在同一份代码上补跑了这一局"),不写它的*名字*。
- **产物血统词**:①删掉修饰语,主句保留;②它指的输入差别确实改变读数(换了提示、换了权重、换了枚举),就把那个差别写出来,一个从句,用文档已有的词。**每条都同时报用户**:血统词常常是一格里混了两代产物的自白,"统一重跑"还是"删这一格"是用户的裁定,改词只是遮住它。

**只出现一次的词一律先假定要删。** 一个名词全文只用一次,几乎不可能承重——它是作者写那一句时顺手造的。

**良品名单里的、以及精确的领域术语 → 原样留着。**

**自查(第二趟收尾跑一次)**:候选词按全文出现次数排序,`n == 1` 的逐个问"删得掉吗";`n` 很大但读者仍看不懂的,问"文档里有没有同义词"——**频次不是保留理由**。内部名与血统词读感抓不到,只能 grep:

```bash
for w in "词1" "词2"; do printf '%3d  %s\n' "$(cat <目标文件> | grep -oF "$w" | wc -l)" "$w"; done | sort -n
# 内部名:机器名前缀取自 hostname,路径与产物目录按仓库约定补
grep -noE "$(hostname -s | sed 's/[0-9]*$//')[0-9]*|/home/|/shared/|/tmp/|~/|outputs/" <目标文件>
# 血统修饰语:每条命中问「它说的输入差别写出来了吗」
grep -noE '(重跑|补跑|重打|重算|上一轮|上一版|旧的|第[二三四]次|那份|副本|copy of|re-?scored|earlier)[^。]{0,40}' <目标文件>
```

### 改写纪律

- 只动措辞,不动事实、不动数字、不动结论。**界线**:从 plan / 代码 / artifact **搬运**一条已经存在的事实过来当定义 = 允许;**推断、补全缺失项、扩大结论范围** = 动事实,禁止。表里少两行、九条只列了八条 → 只报不补。
- **删词不许顺手升级主张**:原文只说"打平"就别改成"不输"。
- 每处改动可回溯到 ledger 的某一条,ledger 上没有的地方不顺手改。
- 换了词就全文一致换,别留半新半旧;跨文件同词同改。**派生页**(从某份 md 抄出来的 HTML)换词要连源页一起换;只为仓库外读者删掉的内部名只删派生页,源页的出处节留着。
- 图上画的字、表头与正文同步改;HTML 里的 SVG 文字、`alt`、`title` 也算。
- `sure` + `表面` 的可以只记不改(**预期 50%+ 的条目最终判为无需改,这是正常的**);`承重` 的必须有处置。

## 验收

- 每条 `承重` 和 `局部` 都有处置:删词 / 换词 / 删句 / 加定义 / 报为 bug / 判定无需改(写明理由);C 组每条有删句测试结论;
- 文档级判定每条都有回应(采纳并改结构 / 说明为何不改);
- 要离开仓库的页面,自查里的内部名 grep 零命中;换掉的词全仓无残留(含派生页、图里的字);
- **验收盲读是强制步骤,且必须派给独立 subagent**:你在第二趟里已经被代码污染第二次了,自己重读绝对发现不了残留。HTML 给它重新抽出的文本,不给源码、不给上下文。新一轮不再产生 `承重` 条目才算过;
- 全文没有新增只有本仓库懂的词;
- 汇报分三块,**顺序不能反**:①文档级问题与结构改动 ②发现的 bug(自相矛盾、数值互斥、数目不自洽、文档与实现不符)和要用户裁定的血统词 ③已删的废话与内部名(每条附一行删句测试)、已改的措辞。措辞列表最长但最不重要,放最后。

## 常见错判

| 症状 | 纠正 |
|---|---|
| 边读边 grep 代码"确认一下" | 盲读就作废了;确认放第二趟 |
| 直接读 HTML 源码盲读 | 读者看的是渲染后的页面;先抽文本 |
| 后文有定义就放过 | 定义晚于使用照记,把定义搬到首次出现处 |
| 表头、图注里的词"正文定义过了" | 表图是独立阅读单元,算未定义 |
| 每个没见过的名词都记 → 上百条 | 门槛是"必须重读或翻页",不是"不眼熟" |
| 承重条目 20+ 还在逐词记 | 那是结构问题,转去写文档级判定 |
| 把术语当 jargon 改成大白话 | 领域读者认得的原样留,进良品名单 |
| 标准概念的自造中文写法被放过 | 这类最隐蔽,按"换成通行写法"处理 |
| 发明一个"更清楚"的新词 | 只能用文档已有的词或领域已有的词,否则是新黑话 |
| 看不懂的词一律补定义 | 顺序反了:先试删、再试换成文档已有的词,补定义是第四选择 |
| 只出现一次的自造词被放过 | 默认删。全文只用一次的名词几乎不可能承重 |
| 高频词"改起来太多处"就留着补个定义 | 频次不是保留理由;判据是"文档里有没有同义词" |
| 给产物名、机器名补一句解释 | 内部名只删不补;要交代的是它的内容,不是它的名字 |
| 修饰语读得顺就放过(「补跑的那份」「上一轮的」) | 卡住门槛抓不到血统词;grep 补扫,问输入差别写出来没有,并报用户 |
| 把废话改写得更通顺 | C 组没有改写选项,只删或降级 |
| 删句后不查前后指代 | 被删句喂养的"这个对比"会悬空;删一句要重读整段 |
| 摘要与正文打架,顺手改一处对齐 | 这是 bug,先报;信哪个由用户定 |
| "本页读不懂"被摊成 30 条悬空指代 | 写进文档级判定,正解是加前置概念小节 |
| 只改了派生 HTML,源 md 里旧词还在 | 换词要连源页一起换(内部名除外) |
