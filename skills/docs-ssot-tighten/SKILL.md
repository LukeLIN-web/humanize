# 结果页 SSOT 收紧(数字归 owner → 复本换判决词 → 只写终态)

## 核心测试

对每个数字、每张表问一句:**「删掉它,读者会信错东西,还是只是少看一遍?」**
只是少看一遍的,删。信错东西的,再问第二句:**「它的 owner 是谁?」**
owner 在别处 → 这里换成判决词 + 指针;owner 就是这里 → 保留,且全库只此一份。

判决词 = 「显著超过 / 判等价(带余量) / 显著落后 / 未判定」这四档。跨页转述时
**只带判决词,不带点估计和 CI**——点估计会被抄错,CI 会因簇标签口径微差而对不上,
判决档位不会。

## 数字的三层 SSOT

1. **artifact 层**(`outputs/**/*.json`):数字的最终出处,重算以它为准。
2. **owner 结果页**:该读数唯一的判读落点,数字 + CI + 分母/簇数只写在这里。
3. **其余一切**(别的页、总览页、入口页、memory):只准判决词 + 纯文件名指针。

**并排表例外**(第 3 层唯一的放行):跨场/跨臂并排本身就是某页的产品(régime 梯度表、
传导台账)。这种表可以保留 owner 在别处的数字,但**同一条轴全库只准一张终态并排表**,
表头必须标「本表是 X 轴唯一并排表;数字与各 owner 页同源」+ 自己的 artifact 出处;
其余页的同轴并排(旧的 N 场版被 N+1 场版改写、每页顺手附带列一遍的台账)删成一行
指针 + 判决级摘要。台账被合并进唯一页时,冻结件里的历史点数不回改,台账页标注
「计数以本表为准」。

一条线页数多时建线目录 + 入口页(overview):入口页**零表格、零数字**,
只写终态判决与各页分工,一页一行。

## 六类可删项(分类完再动手,不边读边删)

1. **跨页复述的数字**——B 页把 A 页的读数连 CI 抄一遍当前提。换判决词 + 指针。
   含高危子类:**台账点数计数词**(「已有三点」「五个传导点」)——台账每长一行,
   所有复述过点数的页全部变错(实测同一台账在三页里数出三/四/五点)。计数词一律删,
   改成不带数的指针(「传导台账见 x.md」)。
2. **过程叙事**——「曾记 X 后改为 Y」「51.39→57.71」、收账/探针日期戳、旧错误结论。
   正文只写终态;过程史归「计划决策落账」节与 git 历史。
3. **自证严谨的元叙述**——为证明勤奋而报的中间计数、「我们没有做 X 因为怕 Y」式
   自辩。协议和表格本身承载信任,叙述不承载。
4. **复述 artifact 的表**——整表逐格照抄某个 JSON。留 headline 行 + artifact 路径,
   全表删。两页同一张表 → 只留 owner 页那份。
5. **陈旧对照**——已被改写的旧口径读数还并排摆着。删旧留新。
   ⚠️ 例外见硬保护第 4 条:user 裁定「两读并列」的不是陈旧对照。
6. **写死路径的引用**——`docs/eval_res/analysis/x.md` 缩成 `x.md`(纯文件名约定),
   连代码/JSON 里的 provenance 字符串一起扫(`grep -rn "docs/eval_res"`)。

## 硬保护(永不删改)

1. **冻结件**(`*criteria-freeze*` 及一切预注册判据)一字不改——它们是证据,
   不是文档。移动、改引用格式都可以,改正文不行。
2. **口径与边界**:CI 区间与显著性限定词、分母与**簇数**(功效由簇数定)、
   ITT/无作答口径、「hit@3 实为 hit@1」这类适用边界、执行偏离表。
3. **凭证类日期**:预声明/冻结时间戳、冻结 sha、外部快照凭证——这些日期是证据。
4. **user 裁定并列保留的读数对**(如「区间含 0 的原读数维持原判,新读数另立不改写」)。
   删掉任何一半都是改判。
5. **owner 页上的数字本体**与「计划决策落账」三件套。

## 流程

1. **建 owner 图**:通读目标目录,列出每个 headline 数字的 owner 页。一个数字有两个
   owner 页 = 先裁定谁是 owner(通常是预声明该终点的那页),再动手。
2. **grep 签名数字**:挑每页 3–5 个 headline 数字(带符号原样,如 `+4.00`、`−2.66`),
   `grep -rn` 全目录 + `paper/` + `docs/memory/`,命中数 >1 的逐个分类进六类。
   **同字串 ≠ 同量**:每条命中先读上下文核身份再分类——实测同一个 `−1.79` 在两页里是
   两个完全不同的读数(不同分母不同口径),按字串批量替换必出错。
3. **分类完再动手**:每处改动都能指回第 2 步的某一行;grep 没命中的地方不顺手改。
   **删复本前先验 owner 在场**:被删数字的 owner 页里必须真有这个数(owner 可能在目标
   目录之外,跨目录 grep 确认)。查无 owner 的数字不是复本,是**孤儿**——要么留下,
   要么先把它落进该落的 owner 页再删这里。
4. **动手纪律**:
   - 只删不改数:任何数字要么原样保留要么整体删除,**禁止在删改中"顺手修正"数字**
     ——发现数字错是 bug,单独报,由 user 定信哪个。
   - **并行会话分池**:动手前 `git status` + 逐文件 `git diff`,把目标文件分成
     「干净(HEAD 即现状)」和「别人在改」两池。别人在改的文件,若对方 hunk 与你的
     改动落在同段(同 hunk 纠缠),**不做 hunk 手术**——跳过整个文件,改动留工作树
     随对方批次走,或干脆不改;只有 hunk 完全分离时才选择性暂存。提交时只提交干净池。
   - 换指针用纯文件名;被指的文件名必须真实存在(`find` 验一遍)。
   - **页内重复不清**:headline 答案区与正文表格重复同一数字是结果页模板的要求
     (insight 前置),不属于本 skill 的清理对象;只清跨页。
5. **验收**:
   - 签名数字重 grep:每个只剩 owner 页一处命中(artifact JSON 与进稿管道不算);
   - `git diff` 冻结件为零;
   - 逐页重读被改的页:删完后每句话仍能独立读通(判决词 + 指针足以承接原句的角色);
   - 汇报三块:①删了什么类多少处 ②发现的 bug(数字打架、指针悬空)③行数 delta。

## 常见错判

| 症状 | 纠正 |
|---|---|
| 把 owner 页的数字也删了图省事 | owner 页是数字唯一的家,删了全线失明 |
| 跨页转述保留点估计"方便读者" | 点估计就是会被抄错的那类;只留判决档位 |
| 冻结件里有重复也顺手清 | 冻结件一字不改,重复也是证据的一部分 |
| 「两读并列」看着冗余删一半 | 那是 user 裁定,删了=改判 |
| 删过程叙事连预声明时间戳一起删 | 时间戳证明口径先于读数,是证据不是流水账 |
| 边 grep 边删 | 先建 owner 图、分类完再动手,否则必漏必错删 |
| 顺手把两处对不上的数字改成一致 | 那是 bug,报给 user 裁定,不许抹平 |
| 只清了 md,代码注释/JSON _source 里的路径没扫 | provenance 字符串一起扫 |
| 按字串批量替换同一个数 | 同字串可能是不同读数,逐条核上下文 |
| 把并排表也拆成判决词 | 并排是该页的产品;唯一化 + 标同源,不拆 |
| 删复本时 owner 其实不在场 | 那是孤儿数字,先安家再删复本 |
| 转述句里留台账点数「共 N 点」 | 台账一长全错,计数词删,指针不带数 |
| 跟并行会话纠缠的 hunk 做拆分手术 | 实测拆出来的 patch 会夹带对方改动;跳过整文件 |
