# learn：会话复盘

一件事做完，把这次花了冤枉时间的地方、以后还要再走的路写下来。产出是几处**写进了文件**的改动，不是一份报告。
没有够格的就写「复盘：无新增」，这是常见且正当的结果，不为交差凑条目。

## 1. 抽证据

```bash
python3 -I <本 skill 目录>/scripts/session_evidence.py <session id>            # 五类证据，按 transcript 行号
python3 -I <本 skill 目录>/scripts/session_evidence.py <session id> --at <行号>  # 那一行前后的可读视图
```

session id 是本会话 scratchpad 目录的名字。脚本列出：user 亲手打的每一句（带时间、距上一次回复多久，含干活中途插进来的）、
被打断、失败的工具调用（含子 agent 的）、被 Stop hook 顶回、上下文压缩的位置。压缩之前的事你只剩摘要，以脚本引的原文为准。
像口令的 user 原话脚本会遮掉，引用时也只写行号。

goal 是 hmz run 或派单卡片（有 epic 或 `.humanize/runs/` 记录）的，另跑 `hmz-epic-review` 的 digest，它还给耗时拆分和重复命令。

## 2. 挑候选

按值钱的顺序看：

1. **user 纠正、定规矩**：「不要…」「以后…」「为啥要…」、打断后改了方向、隔很久才回来问「怎么还没好」。原话和日期照录。
2. **同一个错犯了两次以上，或一个错耗掉明显的时间**（重试、绕路、换方案、空等）：找到根因，是环境、集群、工具，还是某条指示写错了。
3. **被钩子或门禁挡回**：挡对了，说明规则不在你会看的地方，让它好找；挡错了是钩子的 bug，去修钩子。
4. **摸出来的多步流程**：这次试了很多步才走通、以后还会再走（装环境、起服务、对齐某个 benchmark 的协议、排某类故障）。

每条候选过三问，任一问答「否」就丢：

- **有证据吗**：transcript 行号、user 原话或报错原文。只凭印象的不写。
- **下次会不同吗**：写进去以后，下一个会话会做一件不一样的事。一次性的事实、这次的实验数字（进 `docs/` 结果页）、
  读代码就知道的，都不写。只写在提交信息里的 user 裁定不算记过。
- **还没记过吗**：用 `grep -R`（memory 里很多条是软链，`-r` 不跟）查 memory 目录、相关 skill、`CLAUDE.md`、项目文档。
  已有就改那一条（补证据、改错处）；记过了还是犯了，说明那条找不到或写得不对，改它的 description 或措辞，不另起一条。

能当场修的先修：环境缺东西就装上、脚本有 bug 就改脚本、钩子挡错就修钩子。修掉了就不必再记绕行；修不掉的（别人的机器、上游 bug）才记。

## 3. 写进唯一的归属

每条只写一处，别处要提就指过去：

| 是什么 | 写到哪 |
|---|---|
| 某个 skill、文档、脚本的指示错了或缺了，导致这次犯错 | 改那个 skill / 文档 / 脚本本身，不另记一条「X 有坑」 |
| 可复用的多步流程，已有 skill 或文档页管这个场景 | 补进那一处 |
| 可复用的多步流程，没有地方管 | 新建 skill，或项目文档里新开一页（见下） |
| 项目的范围、方向决定（做什么、不做什么） | 项目记方向的那一页（idea、todo、计划页），不进 `CLAUDE.md` |
| user 定的、对这个仓库所有人都成立的工作规矩 | 项目 `CLAUDE.md`，照录原话和日期 |
| 修不掉的机器、集群、工具的坑，user 的偏好，个人或机器特有的规矩 | memory |

- `CLAUDE.md` 只收 user 明说的规矩；你自己归纳的道理进 memory，不升级成硬规则。
- memory 按 memory 目录自己的规则写和提交：`readlink -f` 看它落在哪个仓库，那里有 `CLAUDE.md` 就照它（没有就照 system prompt 的「Memory」一节）。
  软链的条目改链的目标（正本），它的索引行也在正本那边的 `MEMORY.md`。
- 新 skill：全 fleet 通用的工作流建在 humanize 仓 `skills/<name>/`；研究、写作类建在 ARIS fork
  （`~/workspace/juyi/Auto-claude-code-research-in-sleep`）的 `skills/<name>/`；只这个项目用的流程写成项目文档里的一页，
  项目 `CLAUDE.md` 里只写路径指过去。description 写清什么时候用、触发词；正文写步骤和每步怎么验，不写这次的经过。
- 流程还没走通（链路没跑完、还停在 `[blocked]`）就先不写成 skill 或文档页，只记已经确定的坑；走通了再写。
- 口令、token、密钥、个人信息不落盘，哪怕 user 在会话里打过。

## 4. 提交

改了仓库里的文件（含进了 git 的 memory 目录）：按那个仓库的流程提交，只带自己改的路径。
共享的 memory 正本由它所在仓库的同步流程提交，照那边的规矩。别的会话正在改的文件不碰（看 `git status` 和 mtime）。

## 5. 报告

收尾消息里每条一行：写到哪（路径）、写了什么（一句）、证据（行号或原话）。没有就一行「复盘：无新增」。
