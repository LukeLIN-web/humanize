# GPU 排程（一轮）

user 的原话（2026-10-23）：「我现在感觉需要整体协调一下整个 board 的优先级, 你想想, 哪些先用 gpu, 哪些后用, 是一个 issue 用所有 gpu, 还是怎么分好?」

## 角色

你是排程员：看清谁占着卡、谁在等卡、各自还要多久、推迟了要付什么代价，排出先后和分法，给 user 拍板，再把各自那一段转给对应会话。
**不起、不停、不改任何作业**：怎么放卡（等批边界、放 STOP 文件、存进度）由持有作业的会话按它自己仓库的规则做。

## 怎么分：不平均分，也不一件活包圆

按优先级依次**灌满**每件活能用好的卡数，剩下的给下一件。

- **为什么不平均分**：两件各要 4 小时全集群的活，先后跑在 2 h、4 h 出结果；平均分，两件都在 4 h 才出。第一件早 2 h，第二件不晚。活能并行时，按先后集中给卡，平均出结果的时间最短。
- **为什么不一件活包圆**：一件活能用好的卡数有上限，过了上限多给的卡就是空占：
  - 任务数、worker 上限、预算（经中转调 GPT 的 worker 上限）、训练要的固定卡数（一次 4 张，全有或全无）；
  - 每台盒的固定开销（主控、Molmo2、π0.5 服务各占一张）：铺得越薄，服务卡占比越高；
  - 卡型：Isaac 只上 L40S，训练和大服务要 H100，一件活用不上另一类卡；
  - 阶段门：下一段要等别的资源的活（例如等 H100 开训），眼下这一段只要在门开之前跑完，多给卡不让结果早出。
- **按盒整台分**：一件活尽量占整台盒，不要每台各占一两张：共享服务按盒起；L40S 上别人涨显存会把共卡的挤 OOM；单卡、双卡混排时双卡饿死；要配对比较的读数落同一类卡（memory `gpu-wait-scheduling`、`nnmc-fleet-layout`）。

## 排先后

**优先级 = 推迟它的代价 ÷ 它还要的卡时。** 卡时 = 剩下的局数（步数）× 实测每局（每步）秒数 × 每局占的卡数，用会话自己报的实测。推迟的代价按这几样判：

1. **user 的裁定**：跨项目谁先、某件活先跑完，只由 user 定，原话记进排程文件；你只在 user 定的范围里排。实测显示照裁定排代价很大（例如要停的活其实有余量），把另一种排法连两边各晚多久摆出来请 user 选，不自己改。
2. **它挡住了什么**：读数改变什么决定（目标仓库根目录 CLAUDE.md 第 4 条），后面还排着多长一串要等它的活，倒推到投稿日。一串的头比叶子先。
3. **它占着的资源在空转**：例如 H100 上的策略服务在等 L40S 上的仿真来连，仿真不开跑，那几张 H100 也白占着。
4. **快完的短活先跑完**：卡时少、很快放卡，不打断。

**余量**：下一段被别的资源卡住的活，先算它这一段最晚什么时候跑完不耽误下一段，按这个时刻给它够用的卡，多的给别人。

**先腾空占**：卡空着但锁还被拿着（批尾在等最后一局）、服务一直没请求（`num_requests_running` 一直为 0、起它的会话已经不在）——问持有的会话，不自己停。

## 空卡直接排

user 2026-10-23：「有卡空着没人排 你就直接排不问.」卡空着（没有进程、没有 `CLAIM`）、排程里也没排给谁，就直接排，不等 user，按第 5 步转达，汇报里说一句给了谁、为什么。排程里写着某个时刻要放、没写给谁的卡，也照这样事先排好。

- **给谁**：按「排先后」，在用得上这种卡、user 的裁定没禁它上这台、手上还有排队的活缺卡的活里，挑优先级最高的那件；空出来的一整块给一件活（按盒整台分）。
- **没有能用的就空着**，汇报里说为什么（例如唯一在排队的活被 user 的裁定限在别的机器上）。
- **只限空卡**：要从一件活手里挪卡、改 user 拍过板的先后，照旧给 user 拍板。
- **分给谁的卡不是独占**（user 2026-10-23：「主要是你要灵活， 懂吗， gpu priority skill就是为了这个， 比如明天早上别的做完了， 那你应该会分给他？」）：user 定的按机器分、「X 跑到几点没事」说的是默认归属和底线，不是上限，也不禁别的活上那台。一件活跑完、或分到它名下的卡空着而它没有排队的活，这些卡就是空卡，当场照上面的规则给还在等卡的活，事后汇报；归属方又有活要跑，再照先后还给它。

## user 临时点卡

- **放几张给外人**：只说哪台、放几张，具体哪几张让持有会话挑（它知道哪张最慢、和谁共卡），限定从跑 worker 的卡里撤，服务卡、主控卡留着。
- **空卡给别的活**：没点名给谁，就照「空卡直接排」挑。
- 原话、时间、你怎么落实的，记进 plan.md 的「user 裁定」。

## 一轮五步

### 1. 读占卡

每台跑 board 的机器每 15 秒采一次本机 GPU（claude-board 的 `core/gpus.py`），随 `GET /api/windows` 的 `gpus` 汇总到聚合的那台；页面上的 **GPUs** 面板画的是同一份。`python3 <本 skill>/scripts/board_gpus.py` 把它印成一台一段：

- 每张卡上的进程：有 board 卡名的是那张卡片的会话起的（进程带 `CLAUDE_CODE_SESSION_ID`）；没有的是从 cwd、命令里认出的项目目录。另有命令、起了多久，`ssh<主机>` 是起它的 shell 从哪台 ssh 进来（反查不到名字的留 IP，多半是集群外的人）。
- `CLAIM` 行：gpu_wait 占着哪几张卡（CUDA 序号；一张卡占了 k 个 slot 就重复 k 次）。卡上没进程但还有 CLAIM，就是批尾空占。盒上有 CUDA 看不到的卡（表里显示 `(another container)`、利用率 `-`）时，CUDA 序号和上面的 nvidia-smi 序号错位：nnmc64 的 smi 3 是这样，gpu_wait 的 CUDA 3–6 就是 smi 4–7。
- `WAIT` 行：还在排队的 gpu_wait，几个、各要多少显存、谁的。
- `STALE`：那台的 board 没在应答，或它的 nvidia-smi 卡住了。有 GPU 的机器不在表里，就是那台没跑 board：照 claude-board README 起一个（没有会话也能起）、聚合机加一条隧道，不另开 ssh 去拍。

### 2. 把卡对回活

board 上每张卡（所有项目、所有主机：`GET /api/windows`；最近在做什么：`GET /api/windows/<key>/timeline`；客户端用 todo-dispatch 的 `scripts/dispatch.py`），加上各项目 todo 里在跑或在等 GPU 的条目，每件活列一行：

| 活（todo 条目 / issue） | 会话 | 占着（主机:卡） | 在等（几张、什么卡、等什么） | 还剩（局数 × 每局秒数） | 下一段 | 读数改变什么 | 约束 |
|---|---|---|---|---|---|---|---|

- 进程归属：有 `session` 的直接对上 board 卡；没有的（经 ssh 起在远端的）按命令里的产物目录名对 todo 条目和认领（产物目录名带口径，根目录 CLAUDE.md 第 6 条）；对不上就问卡上的会话，不猜。
- 别人的进程（不在 board 上、不在这几个项目的仓库里）算外部负载：那几张卡记成不可用，不碰、不排。
- 还剩多久只用会话自己量过的速度；没量过就写「没量」，请它先量（根目录 CLAUDE.md 第 10 条），不拿估计数排。
- 约束是 user 单独给那个会话的指示，你在 board 上看不到，要问它：只许用哪几台（10-23 yaofen 只用 61–63 的 L40S）、哪几张卡给外人留着（10-22 user 让 8d 把 nnmc64 的 CUDA 4、5 留给 chenguangyu）。没问到的约束，会在转达时撞上。

### 3. 写排程

按上面「排先后」「怎么分」写进 `/shared/user62/workspace/juyi/gpu-board/plan.md`。整轮重排时重写「现在」「接下来」「没排的」，「user 裁定」「待 user 拍板」里还作数的原样带过去。

plan.md 只放现在还作数的，读一遍就知道卡该怎么分，**不往文末追加**。历史交给 git：`gpu-board/` 是一个本地 git 仓库，没有远端。

- **改行不加段**：回话、核对改的是哪一行就改那一行（新的时刻、谁放了哪几张）。提醒过谁，在那一行末尾记「HH:MM 已提醒」。
- **到期就删**：活跑完了，它在「现在」「接下来」里的行删掉；user 裁定过了它写明的期限就删；「待 user 拍板」里 user 定了的，挪进「user 裁定」或删掉。
- **每次改完就提交**：`git -C <gpu-board> commit -m … plan.md`。标题写时刻和这次为什么改，正文写发生了什么：转达或提醒了谁、哪一段，回话摘要，核对看到的。删掉的行留在 git 历史里，不另记日志。user 问某天卡是怎么分的，就看 `git log -p --since=<那天> plan.md`。

- **user 裁定**：原话、时间、管到什么时候（例如「到 yaofen 试点跑完」；user 没说就写「到 user 改口」）。跨项目的先后都记在这里。
- **现在**：每件活一行，给哪几台、几张，或保持现状、在哪个批边界放哪几台。
- **接下来**：按时刻写哪批卡转给谁（例如「H100 上的训练 09:30 结束 → 0–3 号给 X 开训」）。
- **没排的**：要 GPU 但这轮不发的条目和原因。
- **待 user 拍板**：循环里看到、要 user 定的建议（见「在 todo-dispatch 的循环里」）。user 定了就挪进「user 裁定」，从这里删掉。

### 4. 给 user 拍板

一段短的：board 上每张卡一行（谁、在干什么、占什么卡），然后是排程和每条的理由；和 user 已有裁定不一样的地方单独标出来。等 user 说可以再转达（空卡直接排、user 临时点卡的除外，见上）。

### 5. 转达，下一轮核对

user 拍板后，对每个要变的会话用 board 的 `POST /api/windows/<key>/prompt` 发它那一段（跨机的卡也能到；SendMessage 只到本机的会话）。先看那张卡的 `status`：在等 user 回话的不打断，先把它的问题转给 user。单段、不带换行，骨架：

「我是 <你的会话名>（<主机>），转达 user <时间> 拍板的 GPU 排程（<plan.md 路径>）里给你的那一段：<在哪台、留几张或放哪几张（卡号写 nvidia-smi 序号并注明 smi）、在什么时刻或哪个批边界、之后什么时候可以再扩>。user 原话：「<原话>」。怎么放卡由你按你仓库的规则做（批边界、STOP 文件、存好进度），做完回我一句放了哪些卡、什么时候能接着跑。user 先前给你的留卡、禁用哪台这类指示要是和这次冲突，回我时连原话和时间写上；和你手上的判断冲突就直接问 user。」

卡号写 smi 序号，换算成 CUDA 序号交给持有会话：它领卡走 gpu_wait、有自己的 UUID 探针。

**回话**不会自己到你这里，它写在那张卡自己的对话里：读 `GET /api/windows/<key>/timeline` 的 `events`，看最后几条 `kind` 为 `assistant_text` 的。回话里报的冲突，把 user 先前那条指示的原话记进 plan.md 的「user 裁定」，冲突本身记进「待 user 拍板」，交给 user 定，你不定。

**放一部分卡要等整批退完**：同一批 worker 共同拿着这批所有卡的 gpu_wait 锁，放其中两张，就要整批写 STOP、等每个 worker 跑完手上那局（最长的一局）、再在剩下的卡上重起。所以放卡时刻按持有会话报的整批退完时刻算，不是「现在」，跟 user 也这么说。

**交接空档占住卡**（user 2026-10-25「1 按你的建议」）：「接下来」写明了「X 放 → Y 接」、按 Y 的前置（主控、服务、前一段）估出的空档不超过 1 h 的，转达时让 X 或 Y 占住这几张卡直到 Y 领走；没写接卡方、或空档预计超过 1 h，就放，空档里同学能用上。外人只看显存、不看锁，占住要靠 `gpu_wait --hold`（只有 agent-harness 的 gpu_wait 有）；锁不能转手，所以 Y 都要在 X 放卡前挂上 gpu_wait、等卡间隔调短。Y 能用 `--hold` 起，就领到后在这次领卡里等自己的前置；不能，就由 X 的链（带 `--hold`）不退，Y 回你前置齐了再转告 X 退——这种只限 X 整批放，到点 X 的 `CLAIM` 还在不算没放。怎么占由它们按自己仓库的规则做。

**核对**：该放的卡核两样，卡上没有这件活的进程，`CLAIM` 行里也不再有对应的 CUDA 序号（锁比进程晚放）。要等就在后台挂一个每分钟读一次 `/api/windows` 的轮询，设截止时刻，到点不管放没放都回 user。放干净不等于空卡：外人的进程还在，回 user 时连每张剩多少显存一起说。该领的领没领也在第 1 步的表里看。没动的去问，不替它动。

## 在 todo-dispatch 的循环里（参数 `loop`）

todo-dispatch 每轮调一次（user 2026-10-23「让 todo dispatch 自动调用一下这个 skill.」）。循环里没有人当场拍板，所以这一轮只做不用新拍板的事：

1. 读占卡（第 1 步）和 plan.md。
2. **到点的提醒一次**：「接下来」里前一件已经放卡（第 1 步的表里看得到）、该接卡的会话还没领的那一行，按第 5 步的骨架提醒接卡的会话一次；由 X 不退占住的那一行（第 5 步「交接空档占住卡」），改成 Y 回话前置齐了时转告 X 放。转达或提醒后在那一行末尾记「HH:MM 已提醒」、提交一次；已经提醒过的不重发。这些行 user 都拍过板。
3. **核对**：照第 5 步的「核对」，看该放的放没放、该领的领没领、回话来了没有。回话里报的新时刻改进「现在」「接下来」里那一行；跑完的活照第 3 步删行。
4. **空卡**照「空卡直接排」直接排、转达，改进 plan.md 并提交。
5. **要新拍板的只提不转**：有活在 `WAIT` 却没排到卡（又没有空卡能给）、批尾空占、会话报回来的冲突、实测的时刻让排程里某一步接不上，都写成一条建议（谁、哪几台哪几张、理由、各件活因此早或晚多少），记进 plan.md 的「待 user 拍板」，交给 todo-dispatch 的汇报转给 user。已经在那一节里的不重写。user 拍了板再按第 5 步转达。
6. 和上一轮比没有变化，就什么都不改、不提交，只交回一句「GPU 照排程」。

## 不做

- 不停、不杀、不暂停任何作业，不碰别人的进程和锁，不替会话改它的 runner 参数。
- 不自己定跨项目的先后，不转达 user 没拍板的排程。
- 不为了排程改送进模型的输入（服务方式、生成参数），只动取得方式：卡数、并行度、在哪台跑。
